# ADR-0001：以独立根提交发布 PikaDesk

## 状态

已接受

## 日期

2026-08-27

## 背景

PikaDesk 在 TCHESS 固定代码基线上完成了大规模产品化与独立实现。直接公开包含全部上游提交的开发历史虽然技术上可行，也不会自动成为 GitHub Fork，但页面会把项目呈现为一条上游分支，削弱 PikaDesk 的独立产品身份，并让新贡献者难以快速识别当前系统边界。

同时，PikaDesk 是 GPL v3 衍生作品。独立仓库不能被误解为取消上游版权、许可证或来源归属。

## 决策

公开 `main` 使用一个包含当前完整源码、测试和工程文档的独立根提交。TCHESS 的项目地址、固定基线提交、GPL v3 许可证及资源归属继续记录在 `LICENSE`、`NOTICE.md` 和 `docs/third-party.md` 中；`upstream` remote 保留用于来源核对。

历史改写前创建完整 Git bundle，记录旧开发历史和所有引用，使审计或恢复仍然可能。该 bundle 只作为本地恢复材料，不进入公开仓库。

## 考虑过的方案

### 保留 99 个连续提交

优点是公开所有开发与上游历史。缺点是 GitHub 页面和克隆历史以 TCHESS 为叙事起点，不符合独立项目的交付表达；上游历史本身已经由上游仓库公开维护。

### 在旧历史上仅重写 README

改动小，但不能解决提交图和项目身份不一致的问题，新智能体仍需穿过大量与当前产品边界无关的历史。

### 删除归属并当作全新原创项目

不采用。该方案不准确，也违反项目对 GPL、版权和第三方贡献的尊重。

## 后果

- GitHub 首页与提交图以 PikaDesk 为项目主体。
- 克隆仓库即可获得完整当前源码、测试、规格、实施记录和智能体指南。
- 逐提交开发考古不再位于公开 `main`，但由本地完整 bundle 保留。
- 所有后续提交都从独立根提交继续，第三方归属和 GPL v3 义务保持不变。
