# PikaDesk 交付就绪报告

日期：2026-08-29

范围：Windows x64 本地开发 `app-image`，不是公开发布审批。

## 决策

- **本机开发镜像：GO**。两阶段 `jlink + jpackage` 镜像已从 `PikaDesk.exe` 首次启动；真实界面完成 master 引擎分析与个人 OBK 查询，关闭后应用/引擎残留为 0，236 项静态包哈希全部复算一致。
- **公开安装包/对外发布：NO-GO**。`model/yolov11.onnx` 的训练数据、权重来源与独立再分发授权仍未闭环；耐久测试也尚未完成连续 1,000 半回合。
- 该结论不允许把“个人非商用”解释成第三方资源再分发许可，也不允许修改鲨鱼授权或复制其私有资源。

## 打包架构

直接使用 JavaFX Maven 插件的 `javafx:jlink` 会失败，因为 `slf4j-api 1.7.36`、`jnativehook 2.1.0`、JNA 和 ONNX Runtime 等包含自动模块，而 JDK `jlink` 不接受自动模块。

已验证路线：

1. Maven Wrapper 执行 `clean verify`。
2. Maven 复制运行时依赖到受控暂存目录。
3. JDK `jlink` 只构建必需的 JDK 模块运行时，包括 `java.sql.rowset` 与 `jdk.unsupported.desktop`。
4. `jpackage` 使用预构建运行时，把 PikaDesk 和第三方自动模块放到 module-path。
5. 复制模型、声音、棋盘素材、许可证和第三方清单，校验必要文件并生成 SHA-256 清单。

固定入口为 [`scripts/package-windows.ps1`](../scripts/package-windows.ps1)。生成目录在 `target/windows-app-image/PikaDesk`，可由 Maven `clean` 完整重建。

## 发布与回滚

本地开发镜像只进行人工分发：保留上一份已验证镜像及其 `SHA256SUMS.txt`，新镜像解压到独立目录，先运行主窗口、皮卡鱼接入、棋谱打开和本地测试棋盘冒烟，再替换旧目录。

触发回滚的条件包括：无法启动、资源缺失、出现新的错误落子、识别失败后仍点击、配置损坏或发现许可证/安全问题。回滚时关闭 PikaDesk，恢复上一份完整镜像目录；源代码回滚采用对应提交的普通 `git revert`，不覆盖用户棋谱与开局库。`target/windows-app-image` 是可重建产物，可以通过下一次 `mvn clean` 清除。
