# 规格：流畅只读陪练工作流

## 黑盒对照范围

只读取 `D:\象棋\Config.ini` 中公开可观察的交互设置，并与 PikaDesk
现有界面和测试证据比较。不反编译、不修改鲨鱼文件，不读取或迁移授权状态，
也不把鲨鱼的名称、图像、文案或配置格式复制进 PikaDesk。

## 取舍

| 观察到的交互逻辑 | PikaDesk 决策 |
|---|---|
| 当前引擎、时间、线程、开局库和连接方案分别保存 | 保留 PikaDesk 的独立设置模块；只读连接复用安全默认值 |
| 连接方案强调自动保存和最小等待 | 借鉴为“自动预校准”：模型已定位棋盘时，省去重复的坐标干运行按钮 |
| 最小化窗口禁止连接 | 保留现有目标可见性和窗口身份复核，目标变化立即失败闭锁 |
| 箭头、深度、分数、时间和思考过程可见 | 保留 PV 高亮，并增加独立连接状态，不让引擎信息覆盖连接状态 |
| 大量参数平铺在配置中 | 不照搬；普通用户只看到安全快速路径，高级参数仍可展开调整 |

PikaDesk 不复用旧窗口坐标直接连接。每次由用户亲自选择目标窗口，并重新运行
本地模型定位；这比无条件恢复旧坐标更适合窗口会移动、缩放和换显示器的场景。

## 快速路径

1. 用户保持默认“只读陪练”，点击连线并亲自选择本地棋盘窗口。
2. 模型在当前窗口中找到已验证的经典棋盘后，PikaDesk 使用当前扫描参数完成只读预校准。
3. 向导直接显示“识别校准已通过”；用户只需确认目标属于本人/已授权并启动。
4. 若模型未定位、目标不可见或参数不兼容，退回现有手动校准流程，不猜测、不自动启动。
5. “自动走棋”不使用这条快速路径，仍必须显式完成坐标干运行和授权。

## 状态反馈

主窗口使用独立状态文本表达：

- `等待选择窗口`
- `正在配置本地棋盘`
- `正在同步初始局面`
- `只读陪练已就绪`
- `已同步走子，正在更新建议`
- `已停止` 或带原因的安全暂停

状态接口只接受有限状态和有界详情，不能显示目标截图、完整局面或机器标识。

## 性能预算

- 默认扫描间隔保持 100 ms，不在没有测量时盲目调低。
- 经典离线测试棋盘的稳定局面识别和红/黑方向判断均要有可复现计时。
- 目标走子到 PikaDesk 棋谱同步的目标为 p95 不超过 800 ms；第一条可用 PV
  的目标为 2 秒内。达不到时先定位截图、ONNX、稳帧或界面线程中的实际瓶颈。
- 任何性能优化不得降低完整局面、合法着法、双稳帧和目标身份校验。

2026-08-29 本机离线基线：模型初始化 136 ms，首帧/稳定帧识别分别为
115/120 ms；20 步视觉确认平均 380 ms、P95 416 ms、最大 447 ms，全部
确认成功。已有最终界面首条 PV 为 1,454 ms。两项均在预算内，故不缩短
扫描间隔，也不放宽双稳帧或合法性校验。

## 验收

- 只读模式且模型定位成功时，打开向导前已经完成预校准。
- 预校准不创建、不武装、不调用任何 Windows 输入协调器。
- 自动走棋模式仍需要原有干运行步骤。
- 连接状态与引擎分析文本分开显示，并在停止后复位。
- 定向测试、完整 Maven `verify`、红/黑离线模型探针和 Windows app-image 打包零失败。
