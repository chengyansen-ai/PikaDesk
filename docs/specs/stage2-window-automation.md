# 规格：第二阶段——通用窗口识别与授权自动执行

## 目标

让用户从当前桌面的通用可见窗口列表中选择自己拥有或双方明确同意的棋盘，
由 PikaDesk 重新识别棋盘、完成坐标干运行，并在 Pikafish 给出着法后通过
现有安全状态机执行一次落子和视觉确认。

本阶段不按软件名称适配目标，不内置 JJ、天天象棋或其他真人平台的窗口特征、
坐标、皮肤、登录、协议、反检测或托管逻辑。

## 技术与结构

- Java 21、JavaFX 23、JNA 5.15、现有 YOLO/ONNX 识别和 Pikafish 协议层。
- `linker`：有界窗口候选、Windows 可见窗口目录、会话内选择令牌。
- `controller`：通用选择对话框；原有连接向导继续负责干运行和授权。
- `automation`：继续复用现有授权、坐标映射、逐事件活动检查和视觉确认，
  不增加第二套输入实现。

## 用户流程

1. 用户在主界面选择“自动走棋”，点击连线。
2. PikaDesk 显示有界的可见顶层窗口列表；用户也可选择“准星点选窗口”。
3. 选定窗口后重新读取窗口身份和客户区，运行模型定位棋盘。
4. 用户执行无点击坐标干运行，并勾选本次会话授权。
5. 只有目标身份、窗口焦点、棋盘范围、方向、主题、模型和授权都通过后，
   输入协调器才能进入已武装状态。
6. 每一步最多发送一组点击；随后必须由稳定新局面确认。失败、失焦、窗口变化、
   用户输入或识别不确定时暂停，不自动重试。

## 威胁模型与边界

窗口标题、类名、进程名、客户区尺寸和导入配置都是不可信输入。

- 冒充：选择令牌只在本次枚举结果中有效；解析后重新验证 HWND、进程和客户区。
- 篡改：导入配置不能继承本次授权；自动模式仍必须重新干运行。
- 信息泄露：不保存截图，不把完整棋盘、原生句柄或机器标识写入诊断。
- 拒绝服务：候选数量、文本长度和最小/最大窗口尺寸均有上限。
- 权限提升：默认仍是只读陪练；列表选择不会跳过授权状态机或视觉确认。

## 始终/询问/禁止

- 始终：每次重新选择和复核；显式会话授权；失败闭锁；本地测试棋盘 E2E。
- 询问：新增可发送输入的模式、放宽主题/DPI、改变确认或重试策略。
- 禁止：平台专用适配器、账号/网络接入、授权绕过、反检测、静默自动武装。

```powershell
$env:JAVA_HOME = 'C:\path\to\jdk-21'
.\mvnw.cmd --batch-mode '-Dtest=TargetWindowSelectionSessionTest,WindowsWindowCatalogTest,ConnectionWizardStateTest,WindowsMoveCoordinatorTest' test
.\mvnw.cmd --batch-mode verify
.\scripts\package-windows.ps1
```

小型测试覆盖候选净化、上限、过期/伪造令牌和自身窗口排除；Windows 集成测试覆盖
真实可见测试窗口枚举；最终只对仓库自带的离线测试棋盘执行自动落子 E2E。

## 验收标准

- Windows 用户可从通用窗口列表或准星选择目标；列表不包含当前 PikaDesk 进程。
- 不可见、最小化、标题为空、尺寸异常和超过数量上限的窗口不会进入候选。
- 伪造或过期选择令牌不能解析为 HWND。
- 列表选择与准星选择最终进入同一连接向导和同一安全执行路径。
- 只读模式仍不创建输入协调器；自动模式仍需干运行和逐会话授权。
- 本地测试棋盘完成窗口枚举、模型定位、自动落子、视觉确认和失败闭锁验证。
- 源码中不存在公共平台名称或专用窗口匹配规则。
