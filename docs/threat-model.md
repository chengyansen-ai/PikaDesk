# PikaDesk 威胁模型

## 资产

- 用户对鼠标、键盘和外部窗口的控制权。
- 棋局、截图、连接配置和本地路径的隐私。
- 皮卡鱼引擎、识别模型、开局库和棋谱文件的完整性。
- 应用的可预测性：遇到不确定状态必须停，而不是猜。

## 信任边界

1. 外部引擎进程及其标准输入/输出。
2. 用户导入的 FEN、棋谱、开局库、图片、模型和连接配置。
3. 操作系统窗口枚举、截图、DPI、坐标和鼠标事件。
4. 可选网络源，如 ChessDB、更新检查和官方引擎下载。
5. 自动化规则及其触发动作。

## 主要滥用场景与控制

| 风险 | 失败后果 | 设计控制 | 验证 |
|---|---|---|---|
| 选错窗口或窗口身份变化 | 点击到聊天、支付或系统窗口 | 人工选择、进程路径/签名/标题组合允许列表、每步复核 | 伪造同标题窗口测试 |
| DPI/缩放/窗口移动导致坐标漂移 | 错误落子 | 每步重新定位、边界检查、视觉确认 | 100/125/150/200% DPI E2E |
| 识别低置信度或非法局面 | 引擎输入错误并误点 | 置信度门槛、棋子数量/将帅/连续性/合法走法校验 | 噪声与缺子数据集 |
| 动画尚未结束 | 把中间帧当成新局面 | 稳定帧窗口、哈希一致、超时停止 | 慢动画/卡顿测试 |
| 引擎卡死或输出恶意长行 | UI 卡死、资源耗尽 | 行长、队列、内存、时间上限；可终止进程 | 假引擎故障注入 |
| 配置中的任意命令 | 本机命令执行 | 不接受 shell 字符串；智能脚本只支持白名单 DSL | 注入字符串单元测试 |
| 恶意棋谱/开局库/图片 | 解析崩溃、路径穿越、内存耗尽 | 文件大小、格式、维度、路径和记录数上限 | 模糊与边界输入测试 |
| 下载被替换 | 执行恶意引擎/模型 | 官方 HTTPS、显式来源、SHA-256、用户确认 | 哈希不匹配测试 |
| 自动化无法及时停止 | 连续错误点击 | 全局停止、事件发送器原子禁用、失焦即停 | ≤100ms 停止测量 |
| 崩溃后自动恢复 | 未确认状态继续点击 | 自动化状态不持久化为“运行”；重启必须人工确认 | 崩溃恢复 E2E |
| 用于公共平台作弊 | 账号处罚、破坏公平 | 不提供平台预设、反检测或无人值守模式；文档明确范围 | 发布审查 |

## 自动化状态机

```text
DISABLED
  -> ARMED（用户选择并授权目标）
  -> OBSERVING（稳定截图）
  -> RECOGNIZED（高置信度且合法）
  -> THINKING（引擎请求有截止时间）
  -> READY（目标身份和局面再次一致）
  -> EXECUTING（最多一个走法）
  -> CONFIRMING（新局面必须与预期一致）
  -> OBSERVING

任一检查失败 -> PAUSED
紧急停止/目标丢失/应用退出 -> DISABLED
```

实现约束：一次逻辑走棋可以包含多个低层输入事件，但每个移动、按下或释放都必须通过当前执行许可。序列中的等待和延时不持有状态机锁；紧急停止会清除授权并使当前许可立即失效，已失效许可不能再发送后续事件。单个低层事件发送器必须是短时、有界的操作系统调用，不能在许可内部休眠。

## STRIDE 摘要

- Spoofing：窗口伪装；用多属性身份和人工确认降低风险。
- Tampering：引擎、模型、配置被替换；用哈希、原子写入和来源清单。
- Repudiation：无法解释为何点击；记录脱敏审计事件和状态迁移，不记录账号或完整隐私截图。
- Information disclosure：截图/路径泄露；默认只本地保存，诊断包需用户预览。
- Denial of service：恶意引擎/文件耗尽资源；使用上限、超时、取消和隔离进程。
- Elevation of privilege：脚本变成本机命令；DSL 白名单，不调用 shell，不提升权限。

安全脚本采用 `PDSCRIPT 1` 严格语法；动作参数只可能是枚举或有界整数。解析器和执行器没有进程、文件、反射或网络接口；未知字段、多余参数及版本均失败。脚本的授权走棋请求只产生高层信号，并在发送前读取真实自动化状态机；低层输入仍只能通过一次性 `EventPermit`。
