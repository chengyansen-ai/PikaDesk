# 实施计划：PikaDesk

## 总览

采用风险优先的垂直切片：先建立可复现构建和现有行为特征测试；然后跑通自带本地测试棋盘的“识别—分析—授权落子—确认—停止”闭环；再扩展多引擎、策略和工具集。每个切片都必须保持应用可构建、可测试、可回滚。

## 依赖图

```text
规格批准
  -> 可复现构建 + 测试框架
      -> 现有引擎/规则/连接器特征测试
          -> 自动化安全内核
              -> 本地测试棋盘闭环
                  -> 配置向导和通用授权窗口
      -> 多引擎注册表 -> 五引擎工作台
      -> 分支棋谱模型 -> 分析树/报告
      -> 时间策略内核 -> 安全脚本 DSL
      -> 格式适配 -> 开局库批处理/引擎赛
所有 P0/P1 切片 -> 稳定性验收 -> Windows 打包
```

## 阶段 A：工程基线

- 任务 0：用户确认规格与安全边界。
- 任务 1：建立 Maven Wrapper、JUnit 5、固定 JDK 说明和基线构建。
- 任务 2：补齐 PikaDesk 身份、上游归属、许可证与二进制来源清单。
- 任务 3：为规则、UCI/UCCI 和现有连接器编写特征测试。

### 检查点 A

- `mvnw test` 与 `mvnw verify` 在干净检出上通过。
- 不运行外部自动化也能完成手动分析主流程。
- 用户审阅第一份基线测试报告。

## 阶段 B：安全的自动走棋最小闭环

- 任务 4：定义 AutomationStateMachine、授权目标和紧急停止接口。
- 任务 5：建立自带的本地测试棋盘与确定性截图夹具。
- 任务 6：把识别结果变为带置信度和合法性理由的结构化结果。
- 任务 7：实现坐标校准、单步执行和执行前身份复核。
- 任务 8：实现落子后视觉确认、超时、暂停和诊断事件。

### 检查点 B

- 本地测试棋盘连续 100 个半回合零误点。
- 失焦、移动、缩放、识别错误和引擎超时均安全暂停。
- 紧急停止延迟有自动测量结果。

## 阶段 C：可日常使用的分析工作台

- 任务 9：引擎注册表与最多五个独立进程的资源预算。
- 任务 10：五引擎/MultiPV 对比工作区。
- 任务 11：不可变分支棋谱模型和往返测试。
- 任务 12：分支树、注释、评估曲线和关键着标记。
- 任务 13：连接配置向导与可移植配置包。

### 检查点 C

- 五引擎可同时分析同一局面并单独停止。
- 保存、关闭、重开后引擎与连接配置一致。
- 分支棋谱导入、编辑、导出无主线丢失。

## 阶段 D：VIP 工具集

- 任务 14：比分/阶段/剩余时间策略内核。
- 任务 15：事件—条件—动作白名单脚本 DSL、预演和审计。
- 任务 16：棋谱格式适配器的样例与往返测试。
- 任务 17：开局库批处理、去重、进度、取消和报告。
- 任务 18：引擎循环赛、淘汰赛、断点恢复和结果导出。
- 任务 19：中文语音、SVG/PNG 棋子和主题回退。

### 检查点 D

- 对照矩阵全部 P1 项具备证据。
- 脚本无法调用任意系统命令或越过授权目标。
- 大批量任务可取消、可恢复、失败可解释。

## 阶段 E：稳定性与发布

- 任务 20：1,000 半回合自动化可靠性测试和 DPI/主题矩阵。
- 任务 21：依赖、许可证、模型、隐私和安全审计。
- 任务 22：Windows 运行时镜像/安装包、首次启动向导和用户手册。
- 任务 23：逐行 VIP 对等验收与 v1.0.0 发布候选。

## 增量 F：只读实时陪练

- 任务 24：把现有观战链路收紧为默认“只读陪练”，复用稳定识别、方向判断、棋谱同步和 Pikafish PV 提示。
- Windows 连接在只读模式不得创建或武装输入协调器；自动走棋仍是独立、明确选择且仅限授权目标的模式。
- 风险优先顺序：先证明零外部输入，再验证红黑/方向和一步棋同步，最后做本地测试棋盘实机验收与重打包。

### 检查点 F

- 只读模式的契约测试证明外部输入能力不可达。
- 红方在下、黑方在下、普通着法和吃子均能同步；不确定画面安全暂停。
- 推荐着法只高亮预演，真实棋谱只记录目标窗口已经确认的着法。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| TCHESS 无测试且耦合 UI/系统调用 | 高 | 特征测试 + 边界接口，不做大爆炸重构 |
| 截图/点击受 DPI、渲染和动画影响 | 高 | 风险优先闭环、自带测试棋盘、每步确认、失败即停 |
| 多引擎耗尽 CPU/内存 | 高 | 全局资源预算、进程级超时、默认保守配置 |
| 模型/权重许可不清 | 高 | 模型清单、来源与哈希；不清楚就不随包分发 |
| 追求逐像素模仿导致侵权或差 UX | 中 | 只对齐任务能力，采用独立设计系统 |
| 功能面过宽拖慢可用版本 | 中 | P0 闭环先行，P1 分批验收，P2 不阻塞发布 |

## 开放问题

- PikaDesk 名称是否保留。
- 鲨鱼免费版是否需要在隔离环境做黑盒 UX 对照。
- 首个通用目标确定为用户自有的 Windows 本地人机棋盘；额外主题在取得测试截图后逐项验证。
